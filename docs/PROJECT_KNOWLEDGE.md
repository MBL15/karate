# База знаний Karate Hub (Seishin)

Документ для разработчиков и агентов: что это за продукт, как устроен репозиторий, где искать код и как не сломать безопасность.

## 1. Продукт

**Karate Hub** — веб-приложение (и APK через Capacitor) для секции каратэ:

| Роль | Интерфейс | Задачи |
|------|-----------|--------|
| **COACH** | `/coach/*` | Группы, расписание, посещаемость, ученики, бейджи/пояса, соревнования, чаты, платежи |
| **PARENT** | `/app/*` | Дневник ребёнка: дом, профиль, достижения, история, соревнования, документы, чат |

Язык UI — **русский**. Маркетинговые страницы: `/`, `/for-parents`, `/for-coaches`.

## 3. Безопасность и доступ

### Spring Security (`SecurityConfig`)

- Stateless JWT, `JwtAuthenticationFilter`.
- Явные матчеры:
  - `/api/auth/**`, `/health`, `/api/info` — публично.
  - `/api/coach/**` — роль **COACH**.
  - `/api/parent/**` — роль **PARENT**.
  - `/api/payments/**` — authenticated; PATCH и reminders — только COACH.
- **`anyRequest().permitAll()`** — всё остальное под `/api` без матчера **публично**. Новые эндпоинты сразу добавлять в матчеры.

### Проверки в сервисах

- **Тренер:** `CoachAccessService` — группа доступна, если пользователь владелец или `GroupAssistant` того же клуба.
- **Родитель:** `ParentAccessService` — ребёнок только через `ParentStudentLink`. Код клуба многоразовый: родитель вводит его и создаёт профиль ребёнка в этом клубе.

### Контроллеры

Дополнительно: `SecurityUtils.requireCoach()` / `requireParent()`.

## 6. Фронтенд

### Точки входа

- `src/main.tsx` — React root, провайдеры.
- **`src/App.tsx`** — единственное место объявления маршрутов.

### Маршруты

**Публичные** (`SiteLayout`): `/`, `/for-parents`, `/for-coaches`, `/login`, `/register`.

**Тренер** (`ProtectedRoute` role=COACH, `CoachLayout`):

| Путь | Страница |
|------|----------|
| `/coach` | `CoachDashboard` — главная: шапка тренера, тренировки по дням (отметки, оплата, значки), статистика, расписание групп, «Что требует внимания» |
| `/coach/students` | База учеников |
| `/coach/tools` | Инструменты (заглушки/ссылки) |
| `/coach/attendance` | Посещаемость (query: groupId, date, time) |
| `/coach/schedule` | Расписание (`?add=slot` из меню «Создать») |
| `/coach/awards` | Награды |
| `/coach/competitions` | Соревнования |
| `/coach/chat` | Перенаправляет на `/coach`: чат на этом этапе отключён. Страница `CoachChatPage` и `components/chat/` оставлены в коде, но не подключены к маршрутам. |
| `/coach/secret` | Секретная страница |

**Родитель** (`ProtectedRoute` role=PARENT, `ParentAppLayout`): `/app`, `/app/athlete`, `/app/profile`, `/app/competition`, `/app/payments`, `/app/secret`. `/app/achievements` перенаправляет на `/app/athlete?tab=achievements`, `/app/history` — на `/app/payments`, `/app/chat` — на `/app` (чат отключён, `ParentChatPage` не подключена).

- Стиль как у тренера: светлый фон `parent-app-canvas`, белые карточки (`components/parent/parentUi.ts`), акцент зелёный. Тёмная шапка макета только на десктопе.
- Главная (`ParentHome`): `ParentTopBar` (фото, ФИО с выбором ребёнка, пояс, колокольчик), затем «До следующего пояса», плитки посещаемости и достижений, тренировки (последняя и следующая с ответом «придёт / не придёт»), ближайшие мероприятия.
- «Мой спортсмен» (`ParentAthlete`): вкладки «Прогресс» (путь к поясу, факторы, общая готовность), «Статистика» (посещения), «Достижения» (значки `BadgeToken`). Данные грузит `useParentChildData`.
- Готовность к поясу у родителя считает `utils/parentReadiness.ts` по формуле тренера (тренировки 50%, значки 30%, мероприятия 20%, нормы 24/3/1), но по серверным данным. Локальные пояса и значки тренера родитель не видит. Номер кю берётся из названия пояса («7 кю»), иначе выводится цвет.
- Переключение детей везде открывает одну шторку `ChildSwitchSheet` (`components/parent/ChildSwitch.tsx`). На главной и в «Моём спортсмене» её открывает имя со стрелкой, на остальных экранах — кнопка «фото + имя ˅» в шапке (`ChildSwitchPill`). В шторке есть добавление ребёнка по коду.
- Фото ребёнка хранится только на устройстве родителя (`child-photo:{id}` в `useStoredState`, JPEG 256 px).
- **Несколько детей.** `ParentChildContext` дополнительно грузит клуб каждого ребёнка (`clubs`, через `profile`). Флаг `multiClub` включён, если клубы разные. Правило отображения:
  - главная, «Спортсмен», «Мероприятия» — данные выбранного ребёнка; если клубы разные, под именем в шапке виден клуб;
  - в шторке выбора у каждого ребёнка указан клуб;
  - колокольчик и окно уведомлений (`useFamilyAlerts`) — по всем детям сразу, у каждой записи метка «Имя · клуб», нажатие переключает на этого ребёнка;
  - «Оплата занятий» — по умолчанию «Все дети», блоками по ребёнку с клубом и числом неоплаченных месяцев, плюс фильтр по ребёнку;
  - «Мероприятия» без переключателя в шапке. Дети в одном клубе — общий список турниров клуба, внутри мероприятия ответ отдельно по каждому ребёнку (и строка «Не приглашены», если кого-то нет). Дети в разных клубах — под заголовком плитки детей (фото, имя, клуб, счётчик приглашений без ответа), список показывает мероприятия выбранного;
  - профиль — клуб с переключателем по детям.
- `/app/profile` — профиль родителя, а не ребёнка (файл `ChildProfile.tsx`). Всё о ребёнке — в «Спортсмене». На экране:
  - шапка с фото родителя (локально, ключ `parent-photo`), именем, числом детей и логином или телефоном;
  - «Мои дети» с фото; нажатие выбирает ребёнка и открывает `/app/athlete`; там же «Добавить ребёнка по коду»;
  - «Клуб» (`ClubInfoCard`); если детей несколько, над ним переключатель «чей клуб»;
  - «Аккаунт»: «История оплат», push-уведомления («СКОРО»), выход.

  Пояса и переключателя ребёнка в шапке здесь нет.
- `/app/payments` — «Оплата занятий» (`ParentPayments`). Сумм нет: оплата — условная отметка тренера за месяц («Оплачено» / «Не оплачено»), чтобы не забывать, кто оплатил. Оплата через приложение — в планах. Сверху сводка «Всё оплачено» или «Не оплачено: N месяцев», ниже список месяцев. Вход: Профиль → «Дневник» → «История оплат», плашки долга на главной, пункт в боковом меню. Документы родителю не показываются.
- Вкладка «Статистика» (`components/parent/AttendanceStats.tsx`) считает всё из истории посещений: период (месяц, 3 месяца, всё время), посещено, пропущено, процент, сравнение с прошлым периодом, серия без пропусков и лучшая серия, подсказка при 2+ пропусках подряд, график по месяцам за полгода, дни недели, разбивка по группам (если групп больше одной), календарь месяца с перелистыванием. Гостевые визиты в процент не входят.

Редиректы: `/parent` → `/app`; legacy `/profile`, `/achievements`, … → под `/app`.

## 9. Планы на будущее

- **Данные тренера, которых родитель не видит (сводка).** Ответ родителя «придёт / не придёт» уже идёт к тренеру: `SessionAttendanceDto.parentIntent`, показывается в `TrainingsBoard`, `TrainingSheet` и на `CoachAttendancePage`. Уже на сервере: посещения (`markAttendance`), значки из базы клуба (`issueBadge` при `id > 0`), пояс через «Награды» (`assignBelt`), оплаты, документы, мероприятия, сообщения. Остальное хранится только в `localStorage` тренера (`useStoredState`), поэтому родитель этого не видит. Порядок по пользе для родителя:
  1. Пояса с кю и дан, текущий пояс и история аттестаций (`belt-systems`, `student-belts-by-system`, `group-belt-systems`). Нужны сущности системы поясов клуба и `StudentBelt` с датой. В DTO родителя: ранг и название ступени, дата присвоения. Подробнее в пункте «Профиль спортсмена у родителя».
  2. Базовые значки (`PRESET_BADGES`, журнал `issued-badges`). Подробнее в пункте «Значки-награды с картинками».
  3. Причины пропусков (`absence-reasons`, ключ `classKey:studentId`; «Болеет», «Уважительная», «Предупредили», «Без причины»). Нужно поле `reason` у `AttendanceRecord` в `bulk`-запросе и в `HistoryEntry` родителя.
  4. Тема тренировки (`training-topics`). Подробнее в пункте «Тема тренировки».
  5. Отметка «оплачено за месяц» в журнале (`paid-months`, `MonthJournal`). Если у ученика есть серверный `Payment` за этот месяц, журнал меняет его статус через `PATCH /api/payments/{id}` (оплачено → `PAID`, снятие → `PENDING`/`OVERDUE`), и родитель видит то же. Если платежа за месяц на сервере нет, отметка остаётся локальной. Нужен бэкенд: создание платежа за месяц тренером, чтобы локальный ключ убрать.
  6. Рекомендация тренера (`Student.coachRecommendation`). Родитель её видит в «Прогрессе», но у тренера нет поля ввода. Нужен `PATCH /api/coach/students/{id}` с этим полем и поле в `StudentSheet`.
  7. Профиль клуба (`club-profile`: название, описание, адрес, логотип) и фото тренера (`coach-photo`). Родителю полезно для экрана клуба и шапки чата. Нужны поля у `Club` и `User` с выдачей в профиле родителя.
  8. Уведомления родителям. Подробнее в пункте «Пуш-уведомления родителям».
  - Пока нет ни у кого: заметки тренера об ученике, нормативы и физподготовка по ребёнку (конструктор физподготовки результаты не сохраняет). Итоги соревнований тренер вносит локально — см. пункт «Итоги соревнований».
  - Чат тренер ↔ родитель на этом этапе не нужен: маршруты перенаправляют на главные страницы. Сервер чата и экраны остались в коде, если чат понадобится позже.
- **Фото ребёнка от родителя.** Родитель загружает фото (аватар) своего ребёнка в кабинете. Тренер видит его в «Базе»: в карточке ученика и в списках вместо инициалов. Нужен бэкенд: поле фото у `Student`, загрузка через `/api/parent/**` (только для своих детей через `ParentStudentLink`), отдача фото в DTO учеников для тренера.
- **Событие «Аттестация».** Тренер создаёт аттестацию. Кнопка «Сдал на новый пояс» в карточке ученика (`StudentSheet`) появляется только в рамках такого события; сейчас она убрана, чтобы пояс не выдавали преждевременно.
- **Перевод ученика между группами — на сервер.** Сейчас перевод в карточке ученика (`StudentSheet`, блок «Группа») меняет только локальные составы групп (`group-edits`, `utils/groupEdits.ts`): тренер видит изменения везде у себя, но родитель и другие устройства — нет. - **Аудит до входа в кабинет (октябрь 2026).** Исправлено на фронте: истёкший токен (JWT живёт 24 ч) определяется по `exp` в `api/client.ts` и `AuthContext` — сессия завершается, на входе показывается «Сессия истекла»; понятные ошибки сети и 403/5xx без dev-подсказок в проде; вход уже вошедшего пользователя и `/register` перенаправляют в кабинет; после входа возврат на исходную страницу (`location.state.from`); подсказка «Войти как …» при неверной роли; из мастера регистрации убран неработающий шаг «Подтверждение телефона»; согласие с документами (ссылки на `/docs/*`) обязательно для обеих ролей на шаге аккаунта; профиль тренера можно пропустить, дата рождения и стаж необязательны; по личному коду ученика сначала показывается «Это ваш ребёнок?», привязка — после подтверждения; дата рождения ребёнка ограничена возрастом 3–25 лет; неизвестные адреса — страница 404 (`NotFoundPage`), внутри `/coach` и `/app` — редирект на главную кабинета; ячейки кода помещаются на 320 px; поля входа 16 px на телефоне (без автозума iOS); `100svh` вместо `100vh`.
